Runbook

StepActionDetails
1 Detect

Paging signals come from two sources:

  • Synthetic checks on the primary endpoint
  • Customer-reported errors via the support inbox

The on-call engineer acknowledges within 5 minutes.
2 Triage

Reproduce the error locally using the recorded curl from the alert payload:

curl -X GET 'https://api.example.com/v1/health/deep' \
  -H 'Authorization: Bearer $TOKEN'

If the deep health check returns 5xx, escalate to the platform team via the #incidents channel and proceed to step 3.
3 Mitigate

Mitigation options in order of preference:

  1. Roll back the last deploy via the rollback workflow
  2. Shed traffic to the fallback region
  3. Engage the database team for replica promotion
  4. Failover to the last known good snapshot

Document the chosen mitigation in the incident channel before executing.
4 Resolve

Once the root cause is identified, land the permanent fix on the next release train. Update the runbook with any newly discovered failure mode.
