How distributed systems handle partial failure

The first paragraph establishes context for the document. When a system spans multiple machines, any single component can fail at any moment, and the surrounding software must respond predictably.

The third paragraph concludes the section with a summary. Distributed systems force engineers to reason about partial state, retries, and idempotence in ways that single-machine programs avoid.

Implementation example

def call_with_breaker(target, *args):
    if breaker.is_open():
        raise CircuitOpen()
    try:
        return target(*args)
    except TransientError as e:
        breaker.record_failure(e)
        raise
Why this matters in practice

Real systems aggregate these patterns. A web service might wrap a downstream call in a circuit breaker, sit it inside a bulkhead with a bounded thread pool, and add retry-with-jitter on the calling side.
