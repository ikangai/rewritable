# Conformance findings — `seeds/rewritable.html` vs. v1.3 spec

Generated by the autoresearch loop that built `benchmark/scenarios/conformance/`
from the rwa-edit fidelity benchmark v1.3 spec, run against the rwa-edit/1
runtime in `seeds/rewritable.html`.

**Result: 38 / 42 conformance scenarios passing.** Four scenarios surface
real divergences between the v1.3 spec text and the runtime's observable
behavior. The runtime is more permissive than the spec describes in three
places, and silently coerces in one place.

## The four failing scenarios

### CONFORM-10 — split `<script>` tag is silently accepted

- **Spec:** edit whose `find` matches `</script>` and `replace` is empty
  → `parse_error_post_apply` OR `structural_shape_changed` (either is
  acceptable per spec note in §5b.1).
- **Runtime behavior:** apply succeeds, no error raised.
- **Root cause:** `computeShape` (`seeds/rewritable.html:421-427`) tracks
  only `scripts` and `styles` element counts. The HTML5 parser is
  forgiving — when `</script>` is removed, the parser auto-closes the
  script at end-of-input, so `script_count` stays at 1. The post-apply
  shape comparison passes, even though the script's text content has
  swallowed sibling markup.

### CONFORM-11 — top-level `<section>` addition is silently accepted

- **Spec:** edit that adds a new top-level `<section>` via `replace` →
  `structural_shape_changed` with payload `{ shape_before, shape_after }`.
- **Runtime behavior:** apply succeeds, no error raised.
- **Root cause:** same as CONFORM-10. `computeShape` doesn't track
  top-level element count. Adding a non-script/non-style top-level
  element preserves `{ scripts, styles }` and passes the shape check.

**Implication for rules 9 + 10:** the spec wording in `rwa-edit-spec.md`
§13 rule 9 ("structural shape preserved") suggests the runtime should
catch top-level shape changes. The runtime's current implementation
catches only script/style count changes. Either the spec needs to
narrow the rule wording to match the implementation, or the runtime
needs to extend `computeShape` to track top-level element count (and
possibly element-type signature) — at which case SHAPE-01's existing
multi-turn retry path becomes the safety net.

### CONFORM-14 — `concurrent_modify` is signalled via UI only

- **Spec:** two `modify()` calls in flight → second returns
  `concurrent_modify` immediately, before any model round-trip.
- **Runtime behavior:** second call returns `undefined` silently after
  setting an error status string in the palette UI
  (`seeds/rewritable.html:589-591`). No structured failure code is
  propagated to the caller.
- **Implication:** programmatic callers cannot distinguish a
  concurrency-rejected modify from a successful one. This matters for
  any wrapping code (tests, CI, automation, future React-style adapters)
  that needs to react to concurrency.

### EDGE-05 — lone UTF-16 surrogate in `replace` is silently coerced

- **Spec:** `replace` containing malformed UTF-8 (lone high surrogate)
  → `malformed_envelope` (UTF-8 decode failure) before reaching
  validation.
- **Runtime behavior:** apply succeeds; the lone surrogate is preserved
  in the resulting doc string.
- **Implication:** the doc in IDB and the file written by `buildFile`
  may contain ill-formed Unicode. Provider round-trips and downstream
  Unicode-strict consumers (HTML serializers, file I/O on some
  filesystems, IDB read paths in some browsers) may misbehave.

## Tests that revealed surprising shape

- **CONFORM-09** (frozen-zone corruption via context-included anchor):
  passes — the runtime's post-apply byte-identical zone check is the
  backstop the spec promised.
- **SHAPE-01** (model-driven retry path): passes — when
  `structural_shape_changed` *does* fire (the script-count case), the
  multi-turn loop correctly feeds the failure back, the model retries
  with `replace_document`, and `rwa_hist` correctly contains zero
  `edit_batch` records from the rejected first turn (no silent
  escalation).
- **AUDIT-01/02** (history shape): passes cleanly. `edit_batch` records
  carry the envelope; `replace_document` records carry only `reason`.
- **SNAPSHOT-01..04** (bootstrap byte-identity, the rwa container §11
  invariant): all pass. The bootstrap region of `buildFile`'s output is
  byte-identical across edits; only the `INLINE_DOC` literal differs.
- **AUTHOR-01..05** (frozen-zone evolution via external editing): all
  pass. `extractFrozenZones` correctly discovers, removes, errors on
  unterminated, errors on duplicate, and reflects renames.
- **EDGE-07** (IDB transaction abort atomicity): passes. Single
  readwrite transaction across `[rwa_doc, rwa_undo, rwa_hist]` plus
  IDB's all-or-nothing transaction semantics make commitDoc atomic
  against put errors mid-flight.

## Suggestions for runtime evolution (deferred — out of loop scope)

If the user wants to close the gaps:

1. **Extend `computeShape`** to include top-level element count, plus
   maybe a signature like `{topLevelTags: 'div,section,footer', scripts: 1, styles: 1}`. Catches CONFORM-10 and CONFORM-11.
2. **Promote concurrency rejection to a structured `RwaEditError`**.
   Either return the error from `modify()`, or attach a structured event
   to the runtime's status surface that callers can subscribe to.
   Catches CONFORM-14.
3. **Validate UTF-16 well-formedness in envelopes** at the schema layer.
   `String.prototype.isWellFormed()` (ES2024, available in Node 22+)
   tests for lone surrogates. Reject envelopes with lone surrogates as
   `malformed_envelope`. Catches EDGE-05.

Each is small and local — no API breakage required.

## What this benchmark does NOT cover

The 42 conformance scenarios are deterministic and runtime-only. The
fidelity layer (FID/PRES/ID/CONT/DATA/APP/BULK/ROB/INTL/INTERACT/GENRE/
FAIL/DEG categories from spec v1.3 §4 + §5) needs:

- A real model behind OpenRouter (or a stubbed one with realistic tool-use
  outputs).
- The fixture catalog from spec v1.3 §12 (15 templates × 3 wear levels =
  45 fixture files).
- Diff/selector/runtime/language oracles in `benchmark/oracles/`.
- Multi-model coverage (3 reference model classes per spec §10).

That layer is deferred. The directory structure (`benchmark/oracles/`,
`benchmark/fixtures/`, `benchmark/runners/run-fidelity.mjs`) is reserved
in the existing layout and ready to be populated.
