# 2026-05-25 — Landed the import-flow fixes; C2 needed a revert and retry

Followed yesterday's debug pass with `/autoresearch:fix --from-debug` on the same `debug/260523-0739-import-html-bugs/` session. Eight findings to work through; I held C3 (no-CSP) for a spec discussion and fixed the other seven in priority-then-ROI order. Seven commits, all KEEP, no anti-patterns, CLI test suite green throughout. One mid-flight revert on C2 that's worth recording.

Started with the surgical browser-only fixes — H1 added `role="status"` to the `<p id="status">` at line 60 (one attribute, closes WCAG 4.1.3), H2 added `pointer-events: none` to `.drop.busy` (one CSS declaration, makes the busy state actually prevent re-entrant drops instead of just looking like it does). L2 wrapped `new Date(expiresAt).toISOString()` at line 388 in a try/catch with a fallback "Expires within 24 hours" string — the old code would have thrown RangeError and left the share UI stuck on "Publishing…" if the server ever dropped the field. L1 made browser `convertCsv` actually map `result.errors` to the warnings array; the prior code returned `warnings: []` unconditionally despite a comment claiming it mirrored the CLI. Four commits, four files touched once each.

Then the first multi-site fix: M1 — `escapeJsString` doesn't escape `</script>` the way `escapeTL` does, so a filename like `evil</script><svg onload=alert(1)>.md` (Linux + macOS both allow `<` and `>` in filenames) closes the bootstrap `<script>` tag early and turns the rest into HTML. One-line addition in two places: `service/public/import.html:114` and `cli/src/seed.mjs:1366`. Verified with the `/tmp/test-filename-xss.mjs` script from the debug session — the new escape replaces `</script` with `<\/script`, the parser never sees a closing tag, payload neutralised.

C2 was the one that misbehaved. The fix swaps the old regex `_attrIsSafe` for a two-layer check: an `_ATTR_STRIP_RE` normaliser that drops whitespace + C0/C1 controls + Cf-class invisibles (ZWSP, soft hyphen, RLO, BOM, BIDI overrides, word joiner, etc.), then `new URL(normalised, syntheticBase)` for the parse. First attempt I authored the regex character class with literal multi-byte Unicode characters inline. Edit reported success. Then `grep -n "_attrIsSafe" service/public/import.html` returned nothing. `file service/public/import.html` reported `data`, not `HTML document text`. Something in the round-trip had corrupted the encoding. `git checkout -- service/public/import.html cli/src/import.mjs` reverted both files (the C2 changes hadn't been committed yet, so this was clean). Reapplied the same content via a different Edit call — this time the file came back as proper UTF-8 text and grep found the function. I don't have a clean reproduction of what went wrong on attempt 1 vs attempt 2; the working hypothesis is that some intermediate step in the Edit pipeline interacted badly with the long Unicode-literal character class. Lesson for future-me: after any edit that puts multi-byte literals into a regex, run `file <path>` to confirm it still classifies as text before continuing. Cheap check, would have caught this immediately.

The verification harness for C2 (`/tmp/verify-c2-from-files.mjs`) extracted the function from the actual edited file via `import('data:text/javascript,' + encodeURIComponent(...))` rather than re-typing it — that way the test is reading the real source, not a copy. 23 cases pass: 5 classic schemes (javascript/vbscript/file plus https/mailto as positives), the 6 bypass variants from the debug report (ZWSP, soft hyphen, RLO, control char, BOM, newline-in-scheme), three space/scheme edge cases, four src-attribute cases including the SVG-as-img that passes the allow-list but is still safe because of the browser's image-loading sandbox.

Then C1 — the markdown XSS that started this whole arc. marked v14's own README has a 🚨 warning recommending DOMPurify, with the literal `<img src=x onerror=alert('not happening')>` example. Compounding: the seed at `seeds/rewritable.html:849` injects INLINE_DOC via `m.innerHTML` and lines 850-855 explicitly re-create `<script>` tags so they execute. So a bare `<script>alert(1)</script>` in an imported `.md` runs on container open, not just the event-handler variants. The fix was a `sanitizeImportedHtml` function that strips active-content tags (script, iframe, object, embed, svg, math, link, meta, base — both block and self-closing forms), drops `on*=` event-handler attributes (double/single-quoted and unquoted), and runs the new `_attrIsSafe` over surviving `href` and `src` attributes. Every transform appends a warning so the user sees a "(N notes — see console)" suffix matching how `convertCsv` and `convertDocx` already surface warnings.

I chose regex over DOMPurify for mirror-symmetry between browser and CLI — CLAUDE.md's four-sites alignment rule plus the project's no-deps-no-build philosophy made the parser-based approach impractical (would have needed cdnjs+SRI in browser and parse5+jsdom in CLI). This contradicts the May 20 diary entry's "regex drifts from DOM truth" lesson, which I called out in the commit message. The defense: the regex strip is deliberately conservative — over-strips on malformed input rather than under-stripping, which is the safe failure mode. DOMPurify remains worth doing as defense-in-depth, but only if the surface grows.

The C1 verification (`/tmp/verify-c1-md-sanitizer.mjs`) runs 11 cases against the actual edited CLI source: `<img onerror>`, `<script>` tag, `<svg onload>`, `<iframe srcdoc>`, markdown link with `javascript:` href, inline anchor with `vbscript:`, `<details ontoggle>`, ZWSP-prefixed `javascript:` (verifies the C2 layer kicks in here too), `<base href="javascript:">`, plus two negatives (safe `https` link preserved, inline code with literal `<script>` text stays escaped as `&lt;script&gt;`). All 11 pass.

Both verification scripts are in `/tmp/` — they should move into `cli/tests/import-security.test.mjs`. That's the natural follow-up: promote the harnesses, they're the regression coverage for both criticals.

Couple of things carry forward. First, the methodology — scenario → debug → fix as a three-stage chain ran end-to-end. Each stage's output became the next stage's input. The scenario gave the debug pass a catalog of falsifiable hypotheses; the debug pass gave the fix loop a prioritised checklist with code-level evidence and suggested patches. Total: 50 predictions + 9 verified bugs + 7 surgical fixes, all with verification harnesses. Each stage was small in isolation; the chain made the work feel rigorous. Second, the lesson is procedural: after any edit that includes multi-byte literals in regex character classes, run `file <path>` to confirm the file still parses as text. Free check, would have skipped the C2 revert entirely.
