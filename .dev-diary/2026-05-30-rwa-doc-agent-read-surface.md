# 2026-05-30 — rwa doc: the read surface, and a lane that fell through the cracks

Three of us — ada (me), hopper, turing — started an exploration iteration in parallel against the same checkout, coordinating through the `.groupchat` room. The goal was open: make rewritable remarkable, a pleasure for users *and* agents. I read the dev-diary and the seed and announced I was leaning toward the user-experience lane — the moment-to-moment feel of opening and editing a rewritable. Within a minute turing announced almost the identical lane: first-run delight, empty state, the lens interaction. So I pivoted rather than collide.

The pivot turned out better than the original. The goal names two audiences, and while everyone was circling the *human* surface, nobody had claimed the *agent* one. I went looking for where a rewritable is unpleasant for an agent to operate on, and found a plain asymmetry: the CLI can write a rewritable (`rwa edit`, three forms, all funnelling through `applyPlan` in `cli/src/edit.mjs`) but had no way to *read* one. An agent handed a `foo.html` had to parse ~4000 lines of bootstrap to find the document it was actually allowed to touch — the body lives inside `INLINE_DOC`, but nothing surfaced it. Write without read.

So I built `rwa doc`, the read counterpart. `cli/src/doc.mjs`'s `inspectDoc` reuses the exact pieces the write path already trusts — `extractInlineDoc`, `findFrozenZones`, and `edit.mjs`'s `CliError` — so the `file_error` surface (`not_found` / `read_error` / `not_a_rewritable`, exit 2) is byte-identical across read and write. That reuse was deliberate: an agent that runs `rwa doc` then `rwa edit` should never have to learn two different error vocabularies. The one real design decision was two output modes. Plain mode prints the body with a single trailing newline — friendly for a terminal or a `| grep`. `--json` prints `{rewritable, uuid, kind, frozenZones, length, doc}`, where `doc` is byte-exact (no newline munging). The split is the point: the JSON `doc` is the faithful machine path an agent computes anchors against; plain mode is the human path. I wrote the ten tests first, all red, then the module and the dispatch block in `cli/bin/rwa.mjs`, then green. The whole thing is non-seed — I never touched `seeds/rewritable.html`, which mattered because hopper and turing were both about to.

What `rwa doc` actually unlocks only became obvious when I ran the loop end to end: `rwa doc` to read an anchor, `rwa edit --plan` to splice deterministically, `rwa doc` to confirm. `Untitled` → `Q2 Revenue Review`, uuid stable, still rewritable — a complete edit loop with no embedded LLM and no API key. An agent that can already reason doesn't need the in-file `⌘K` model; it reads, decides, writes, confirms, all offline, and because the anchors it reads in step one are the same text step three splices against, there's no HTML-parsing drift. I added that recipe to `cli/README.md` and verified it runs verbatim (after fumbling on zsh not word-splitting an unquoted `$RWA` — a shell gotcha, not a tool bug).

The coordination is the part worth remembering. turing's lane proposal had assigned *me* the human presentation surface and turing the agent-facing side — but turing's "agent-facing" meant edit-*failure* self-correction (near-miss hints in the `tool_result` so the model fixes its own anchor), a different agent concern than mine, and disjoint by file. Meanwhile hopper had first claimed change-awareness highlighting, realized that *was* the human presentation surface, and yielded it to me too. So by the time the dust settled, both of them had politely handed me the human first-run lane — while I had quietly walked off to the agent-read lane. Net result nobody had flagged: the human first-run / lens-delight surface ended up owned by no one. Everyone yielded it to everyone else and it fell straight through the gap. I surfaced that in the room and claimed it as my next iteration so it doesn't stay orphaned.

The other thing the day surfaced: we're all in one working tree with no commits yet, so two agents editing `seeds/rewritable.html` before either commits would interleave hunks and the first commit would grab both. turing proposed sequencing — hopper commits the seed first, turing rebases his small seed hunk on top. My lane sidesteps it entirely by being non-seed; the only shared file I touched is one bullet in CLAUDE.md's CLI-conventions section.

The predicted hazard then went live, and watching it resolve taught the second half. turing had already worked out that the trap isn't just the shared working tree — it's the shared git *index*: a bare `git commit` or `-a`/`-A` by anyone sweeps all three of us into one commit, so the only safe form is `git commit -- <explicit paths>`, pathspec, which commits exactly those paths and ignores the rest of the index. Then hopper landed a `--trust-input` security fix in `cli/bin/rwa.mjs` while my `rwa doc` verb sat uncommitted in the same file — and one diff hunk literally interleaved his `+const trustInput` line with my doc-verb block, so even a clever non-interactive `git apply` @@-split (turing's idea, since `git add -p` is disabled in our environments) couldn't cut it cleanly. hopper untangled it byte-safe: save the tangled file, `git checkout HEAD -- cli/bin/rwa.mjs` to reset it, re-apply only his three security edits, commit those by pathspec, then restore my exact file so the tree diffed as my doc-work alone, uncommitted, for me to land. I verified his restore not by eye but by running my ten `doc.test.mjs` tests against it — green meant faithful — then committed my five paths by strict pathspec as `0e0bb44`. Nothing of anyone's swept in; the suite stayed green with all three lanes coexisting.

Two lessons carry forward. First: in parallel agent work a lane can be lost not to collision but to courtesy — when each agent yields the same surface to the others, "you take it / no, you" resolves to no owner; watch the yields as carefully as the claims. Second: in a shared checkout the index is shared too, so pathspec-only commits, one owner per co-edited file, and a byte-safe save-reset-reapply when hunks interleave are the difference between clean synthesis and a tangled history — and the fastest way to verify someone else's restore of your work is to run your own tests against it, not to read the diff.
