# 2026-06-04 — Architecture doc, and why headless Chrome screenshots a rewritable blank

Built an architecture overview as a rewritable itself — `architecture.html` at repo root, a `document` kind scaffolded with `rwa new --kind document` and then filled by editing the `INLINE_DOC` literal directly. Went with CSS-only diagrams (layer cake, container anatomy, the rwa-edit/1 flow strip) and no JS, partly so it prints clean and partly to dodge the `</script`-in-doc-JS trap entirely. Content came straight from CLAUDE.md and the specs, so the writing was the easy part.

Verification is where I actually learned something. First check was cheap and solid: `rwa doc --json` reported `kind: document`, the title extracted, `frozenZones: []`, and a 17,794-char body — which also proves the `INLINE_DOC` template literal closed correctly, since the CLI walks the same backtick boundary the runtime does. One thing I was deliberately careful about: the doc *talks about* frozen-zone markers and `data-rwa-frozen`, but I kept every mention inside `<code>` spans and never as a real HTML comment or attribute, so none of the prose accidentally created a frozen zone. The `frozenZones: []` confirmed that worked.

Then I tried to screenshot the rendered file and wasted a good twenty minutes. The MCP browser was locked by a parallel teammate ("already running for chrome-profile"), so I fell back to launching my own headless Chrome with `--screenshot`. It came back 25KB and blank — just the runtime chrome (READY badge, the lens input, the ⌘S button) over an empty page. My first instinct was a timing race, so I added `--virtual-time-budget=4000`. Still blank, still ~31KB. That was the tell: virtual time fast-forwards timers, but it doesn't pump IndexedDB's async hydration. The seed reads `rwa_doc` from IDB on boot and only then mounts `INLINE_DOC`; under headless that read hadn't resolved by the time the screenshot fired, and bumping the virtual clock didn't help because IDB callbacks don't ride that clock. So headless `--screenshot` will photograph any rewritable as an empty document — not a content bug, an artifact of how the runtime hydrates.

Pivoted: the only thing I authored that could be visually wrong is the document body's HTML/CSS — the runtime mounting it is stock, already-trusted seed code. So I extracted the body with `rwa doc`, wrapped it in a minimal standalone page carrying the seed's `:root` palette and the `:where(#rwa-doc-mount)` baseline typography (both lifted verbatim from `seeds/rewritable.html`), and screenshotted *that*. No IDB in the path, so it rendered synchronously — 711KB, every diagram and table on-palette and legible. That gave me the visual proof without fighting the async boot.

The lesson that carries forward: you cannot verify a rewritable's rendering with a one-shot headless `--screenshot`, virtual-time or not — IDB hydration won't have run. Either drive a real browser that waits, or render the extracted body standalone with the seed's palette+baseline grafted in.
