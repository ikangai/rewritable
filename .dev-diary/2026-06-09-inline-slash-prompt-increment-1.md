# 2026-06-09 — Inline /-prompt: Increment 1 built and merged

Started from Martin's UX itch: the floating lens breaks the editing flow. He floated two ideas — voice+keyboard as simultaneous channels, or a slash inside the double-click edit that flips you from typing content to prompting the model. We brainstormed it down: voice dies as a foundation because a self-contained file has no honest STT (Chrome's SpeechRecognition phones Google, in-browser Whisper is a multi-MB download) and voice has no pointer anyway — "make *this* formal" needs a selection. The keeper insight came when he chose "lens becomes inline": if the prompt renders at the selection, anchoring becomes implicit — anchor and scope collapse into one concept. Wrote that up as the full design (selection-extent-decides-scope, three tiers), then deliberately cut Increment 1 down to the smallest valuable slice: leading-`/` prompt mode inside the existing double-click edit, Enter routed to the lens's existing `runAnchoredCommand`. Martin added one twist mid-design: Esc demotes the slash to literal text, so `/usr/local` stays typeable.

Executed the plan subagent-driven, eight tasks, two reviews each. The single best moment was Task 3: I had written into the plan, as a verified "fact," that `runAnchoredCommand` resolves its anchor by value (`anchor.start`), so a captured sourceMap entry would survive an intervening `renderDoc`. The implementer hit the plan's verify-before-coding gate, read `resolveAnchorFind`, and STOPPED: it's `sourceMap.indexOf(entry)` — reference identity — and `renderDoc` rebuilds the whole map, so the captured entry orphans and every inline command would have burned three model calls and failed with "anchor could not be resolved." The fix was small and clean: capture `sourceMap.indexOf(entry)` before the restore-render, re-resolve `sourceMap[idx]` after — same committed bytes give an identical rebuilt map. The plan-gate ("if a stated fact is false, stop, don't improvise") paid for the entire ceremony of the process in one catch. The seed even documents this constraint itself in a renderDoc comment I'd missed when writing the plan.

The reviews kept earning their keep on smaller things. One reviewer noticed `handleInlinePaste` preventDefaults and inserts text manually, so no input event fires and the mode discriminator goes stale after a paste — one-line fix, would have become a real mis-route the moment Enter-routing landed. Another found the genuine semantic hole: blur while in command mode committed the `/command` as literal content, violating the design's core promise that the prompt is never content. I decided blur discards (click-away is not consent to a model call), mirroring the failure-restore path. A test-honesty moment worth remembering: the planned "no undo frame burned on failure" check was vacuous because `UNDO_CAP=10` was already full at that point in the suite — the implementer kept it but added a falsifiable hist-top comparison and said so in a comment instead of silently shipping a check that can't fail. The final whole-branch review caught one last divergence: `\/` suppressed prompt mode but committed the backslash, where the lens strips it — fixed to mirror the lens, since the same keystrokes must produce the same bytes on both surfaces.

Two operational notes. The worktree's `.git` pointer file went EPERM-unreadable mid-session (macOS gave it a `hidden` flag + `com.apple.provenance` xattr; even `cat` failed sandbox-off) and wedged every git operation in the worktree until a session restart cleared whatever TCC state was poisoned — `/bin/pwd` worked the whole time, which sent me down a wrong getcwd-debugging path before I cat'ed the `.git` file itself. And I ran Task 8's real-browser pass myself through the chrome-devtools MCP instead of leaving it as a manual checklist: stubbed `window.fetch` in real Chrome and drove the full pipeline — `__setDocForTest` turns out to be exposed in real browsers too, not just jsdom, which makes the seed surprisingly scriptable for this kind of verification. Everything held; merged fast-forward to local main (`2f07d2b`), 78/0 inline-edit, conformance 86/86.

What carries forward: sourceMap entries are identity-keyed and die on every re-render — any future code holding an entry across a `renderDoc` must re-resolve by ordinal, and the selection-scope work in Increment 2 will hit this immediately.
