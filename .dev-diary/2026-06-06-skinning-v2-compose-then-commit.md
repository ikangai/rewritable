# 2026-06-06 — skinning v2: compose-then-commit, and untangling a shared seed

Picked up kepler's skinning thread. v1 (theme-only) had shipped; the piece left was v2 — the always-on L1 content-aware restyle, where applying a skin doesn't just swap a `<style>` block but also has the agent wrap content in `sk-*` hooks, and both land as ONE commit so a single ⌘Z reverts the whole thing. That had been blocked for days on a "compose-then-commit primitive" the design doc kept hand-waving at. dirac's `runtimeRegionCommit` had landed two days prior, which the team thought was the gate, but when I actually mapped the code it turned out region-commit was the wrong tool — it asserts byte-equality *outside* a named span, and L1 touches scattered spans all over the doc.

Before touching anything I ran a fan-out of six readers over the seed to map the seams. The load-bearing discovery: apply and commit are *fused*. `applyEdits` and `replaceDocument` both end with `return await commitDoc(...)`, and the ⌘K loop in `modify()` calls them directly while holding the mutex. There was no "accumulate the agent's edits without committing" seam at all — that absence *was* the gate. So the primitive wasn't region-commit; it was a no-commit mode on the apply path plus a compose hook in `modify()`.

The real design fork was how the combined edit lands as one commit. The design doc had leaned on a seed-baked empty `<style data-rwa-skin="">` placeholder so every skin op stays a content-only `apply_edits` swap (dodging the `structural_shape_changed` guard, which counts `<style>`/`<script>` and would reject inserting a fresh theme block). But the placeholder means changing INLINE_DOC defaults across four sites *and* still needing a fallback for the docs already in the wild. I went the other way: run the agent in no-commit mode to get a validated, shape-checked restyle string, splice the theme block onto it in JS, and commit the whole composed doc once via `replaceDocument` — which is shape-exempt, so the one `<style>` the *runtime* adds is fine, while the agent still can't sneak a `<style>`/`<script>` past `computeShape` in its no-commit pass. Path A: universal, no placeholder, one commit, and it falls out of existing primitives. The "cost" is the history record reads as `replace_document` instead of `edit_batch`, which is cosmetic — one `commitDoc` is still one undo frame, which is the actual promise.

Built it TDD across six commits — noCommit flag, the `modify({compose})` branch guarded so the normal ⌘K path stays byte-identical, `applySkinL1` + per-preset recipes, `sk-*` CSS in the five themes (regenerated the seed `RWA_SKINS` mirror from the canonical `cli/src/skins.mjs` with the same `canonicalEmbed` the mirror test uses), gallery/lens wiring, and a SKIN-03 conformance scenario.

Two things bit, both worth remembering. First: when I went to commit task 1, the seed diff was 30 lines but my change was 9. shannon's 7b worker-CSP work was sitting *uncommitted* in the shared worktree, in disjoint regions of the same file, and a plain `git commit -- seeds/rewritable.html` would have swept her WIP into my commit. I couldn't `git checkout` or `git stash` without clobbering her uncommitted work, and `git add -p` is interactive (blocked). So I filtered the diff to my hunks programmatically and `git apply --cached`'d only those into the index, then committed the index — never touching the worktree, zero race with her live session. Did that for all six commits; her hunk count grew from 3 to 4 partway through, confirming she was still editing, and the untangle held every time.

Second, a genuine reversal: wiring the ✦ gallery swatch to `applySkinL1` instead of `applySkin` broke SKIN-02. The gallery click had been deterministic and offline; routing it through the agent meant that with no backend reachable, clicking a skin did *nothing* — not even the theme. I'd built graceful degradation for a *declining* agent but a thrown fetch propagated straight past the compose fallback to the outer catch. The fix was to make compose mode catch fetch errors and empty responses and fall through to the theme-only commit. That restored SKIN-02 without modifying it, because the theme-only fallback satisfies its assertion. A skin now always lands at least the theme, even offline.

The lesson that carries forward is two-fold: for shared-tree co-editing, `git apply --cached` of a filtered diff is the clean way to commit only your hunks without disturbing a teammate's uncommitted work in the same file; and wiring a previously-deterministic UI affordance to an agent-backed path silently introduces a network dependency that has to degrade, or the affordance just dies when the backend is down.
