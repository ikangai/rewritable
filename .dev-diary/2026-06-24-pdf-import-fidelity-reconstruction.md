The PDF import for 20250025.pdf was losing all layout, turning an invoice into a flat stack of paragraphs. I grepped 20250025.html and saw it lacked tables or any structural markers. Searching for `convert(` in cli/src revealed that cli/src/import.mjs was acting as a prose extractor, discarding columns and alignment. I wrote .probe-tmp.mjs to inspect pdfjs-dist exports like OPS and Util to see what primitives were available. The initial approach of simply pulling text into `<p>` tags was fundamentally broken for structured documents. I rewrote the import logic in cli/src/import.mjs and updated service/public/import.html to perform a geometry-faithful reconstruction. Instead of just pulling text, I implemented positioned text runs and a CTM walk of the operator list for graphics. After editing, I verified the output by running node bin/rwa.mjs import on the original PDF and checking the generated HTML. To ensure the changes didn't break the web interface, I extracted the inline script from service/public/import.html to /tmp/rwa-syntax-check.js and ran node --check. Finally, I updated the design plan in docs/plans/2026-06-24-pdf-import-fidelity-design.md and project memory.
