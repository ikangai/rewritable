Deploy was where I burned time. The memory note says `root@185.164.4.77:/opt/docker/rewritable/ is a flat file sync (not a git checkout). scp changed files, then docker compose up -d --build` — I'd read it but not internalized "flat." My first SSH command after the scp ran `docker compose -f service/docker-compose.prod.yml up -d --build`, mirroring the local repo's layout. Got back `stat /opt/docker/rewritable/service/docker-compose.prod.yml: no such file or directory`. Listed the remote tree and saw the actual layout: `Dockerfile`, `docker-compose.yml`, `server.js`, `public/`, `seeds/`, `demo/` all at the top level of `/opt/docker/rewritable/`, with a tiny `service/` subdir containing only the same `server.js` and `public/` duplicated (presumably leftover from a partial earlier sync). Walked back to `cd /opt/docker/rewritable && docker compose up -d --build` — plain compose, no `-f` flag — and that worked. Container rebuilt, `rewritable-new` recreated and started, logs healthy. Whoever set up that sync flattened the service/ contents into the prod root and the local-vs-prod layout drift never came back into focus.

Verifying the deploy was the second small gotcha. First instinct: hit `https://rewritable.ikangai.com/new` and grep for the new CSS selectors. Got back 5780 bytes of HTML — too small for a container, and `grep overflow-wrap` found nothing. `/new` is an interstitial that triggers a download via JS, not the seed itself. The seed is served directly at `/rewritable.html` — fetched that, got 191KB, grep found `overflow-wrap:anywhere`, `overflow-wrap:break-word`, and `white-space:pre-wrap` all present, plus the `:where(#rwa-doc-mount) figure, pre, table, img { break-inside:avoid }` line no longer mentioning `blockquote`. Plus the explanatory comment block. Deploy verified live.

Lesson the deploy earned: when the deploy procedure note says "flat file sync, not a git checkout," that's a flag the directory layout doesn't mirror the repo — read it as load-bearing, not flavor text. And for live-serve verification: `/rewritable.html` is the canonical seed-fetch URL on the public service; `/new` is just the download interstitial.
