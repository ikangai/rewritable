# 2026-06-06 — webpage-clone: the final review earned its keep

Picked up the `webpage-clone` branch where I'd left it after compaction: all 8 implementation tasks done, 300+ tests green, render-verified, and I'd already been interrupted once while trying to dispatch the final holistic review. Martin came back and said plainly: do the final review and merge. So I did the review I'd skipped — and I'm glad the process forced it, because it caught a real one.

The per-task reviews during implementation had been thorough on the pieces I expected to be dangerous. The SSRF layer in `fetch-page.mjs` had been hammered through two adversarial passes already (the IPv4-mapped IPv6 hex bypass, NAT64, 6to4, multicast — all found and closed task-by-task). I went into the final review braced for the reviewer to find another SSRF hole. It didn't. It tried the decimal/octal/hex literals, the mapped-v6 form, NAT64, redirect-to-internal — all blocked. The fetch layer held.

What it found instead was one level up, in code I hadn't written this branch: `sanitizeImportedHtml` in `cli/src/import.mjs`. Step 3 of that function — the scheme allowlist that neutralizes `javascript:` URLs — only matched *double-quoted* `href`/`src`: `/(\shref\s*=\s*)"([^"]*)"/gi`. That was completely fine for its original caller. `rwa import` feeds it `marked`'s output, which is well-formed and always double-quotes its attributes; the code comment at line 204 even says so explicitly. But `rwa clone` is a *new caller of the same helper*, and it feeds it arbitrary fetched web HTML, where single-quoted and unquoted attributes are everywhere. So `<a href='javascript:alert(1)'>` and `<a href=javascript:alert(1)>` and `<form action='javascript:…'>` sailed straight through, unmodified, into the cloned document — which renders in the `file://` origin via `m.innerHTML`, where a click executes with IDB/OPFS access. A stored-XSS-equivalent in a file we tell people is safe to share.

The fix was small and the shape was already sitting right above it: step 2, the `on*=` event-handler strip, *does* handle all three value forms (`"…"|'…'|[^\s>]+`). I just hadn't carried that same generality down into step 3. Generalized the regex to all three forms across the full reachable URL-attribute set — `href/src/action/formaction/poster/xlink:href` — kept `data:image/*` allowed on `src`, and mirrored it byte-for-byte into `service/public/import.html`, since that browser file is the four-sites-aligned counterpart. Confirmed no behavior change for `rwa import` (marked never emits those other forms). Added the test that should have existed: hostile markup *inside the extracted article body*, not just in the title/provenance path the existing tests covered well. That body-sanitization test is the one that would have caught this, and its absence is exactly why the bug shipped to review.

Then the merge, which had its own wrinkle: this is a shared checkout with four other Claudes (shannon, kepler, dirac, others) live on `main` across several worktrees. You can't `git checkout main` in a second worktree, and you don't want to stomp uncommitted work in the root. Checked the root's tracked tree was clean first, announced in the group chat what I was about to touch, then merged `--no-ff` from the root. Zero conflicts — the three shared files (`CLAUDE.md`, `cli/bin/rwa.mjs`, `cli/src/import.mjs`) were all additive and localized, exactly as shannon had predicted when he said it was disjoint. Verified 31/31 on the merged result before deleting the branch, smoke-tested the real binary (usage→exit1, `127.0.0.1`→SSRF-blocked exit2 no-file), force-removed the worktree (the `node_modules` symlink is untracked and would otherwise block removal — removing the worktree drops the symlink, not its target).

The lesson that carries forward: a shared sanitizer's threat model is set by its *most hostile* caller, not its first one. The moment `rwa clone` started feeding `sanitizeImportedHtml` adversarial input, every "marked's output is well-formed, so this regex is fine" assumption baked into that function became a liability — and none of the per-task reviews caught it because each was scoped to the new files, while the hole was in the old shared one the new feature merely *reused*. The final whole-feature review exists precisely to see across that seam.
